## Design Specificity Verdict

**"Sanitized, not authored"** — รอบแรกลบ *อาการ* ของ AI-template สำเร็จ (emoji/alert/ตัวเลขปลอม/ชื่อ vendor) แต่ *โครงสร้าง* ยังเหมือนเดิม สิ่งที่มาแทนส่วนใหญ่เป็นของกลางๆ ไม่ใช่การตัดสินใจเชิง domain

**Deterministic scan (รอบ2):** 7 findings, **false positive 7/7** (blockquote 2px, มุม viewfinder, ปุ่ม amber contrast 10.4:1) และผ่านทุกด่าน mechanical: emoji 0, alert/prompt/confirm 0, "Gemini" 0 ในฝั่ง client, animate-bounce/ping 0, คะแนนปลอม `|| 95` 0 — **ชั้นผิวสะอาดจริง**

**ตัวบอกที่แรงที่สุดรอบนี้:** ตัวเลขที่เป็นหัวใจของสินค้าไม่ถูกกำกับ — vibration `≤2.0` (ScanMachineView:454) vs `<2.5` (SupervisorDashboardView:497); temp ผิดปกติ `>75` (ScanMachineView:204) vs แดง `>80` (Dashboard:410) ขณะที่ mockData:42 ตีตรา 82.5°C = warning โดยไม่มีกฎเชื่อม วิศวกรซ่อมบำรุงจริงไม่ปล่อยให้ threshold เดียวกันมี 3 ค่า

**Visual world:** radius เดียว (`rounded-[18px]`) ใช้กับทั้งการ์ดเต็มหน้าและชิป 40px; `--shadow-product` และ `--color-tile-dark*` ประกาศไว้แต่ไม่เคยใช้ (dead token จาก template ต้นทาง); type scale = text-2xl → text-base → text-xs ไม่มีชั้นกลาง; **9 ใน 12 หน้าเปิดด้วยบล็อก header เดียวกันเป๊ะ** แล้วตามด้วย filter row + grid การ์ด — หน้าเดียวกันเปลี่ยนแค่คำนาม; Sparkles ยัง import ครบ 12/12 component

## Overall Impression

ชั้นผิวสะอาดจริงและพิสูจน์ได้ด้วยเครื่องมือ แต่รอบนี้ผู้รีวิวขุดลงชั้นโครงสร้าง/domain แล้วเจอของหนักกว่า: flow ที่โกหกว่าสำเร็จ, ข้อมูลปลอมที่ถูกฉีดเข้าใบงานจริง, threshold ขัดกัน 3 ที่ คะแนนเท่าเดิมเพราะ heuristic ที่ดีขึ้น (User Control +1, Error Prevention +1, Help +1) ถูกหักล้างด้วยที่แย่ลงเมื่อมองลึก (Consistency -1, Match Real World -1, Recognition -1)

## Priority Issues

### [P0] 3 flow แจ้งสำเร็จทั้งที่ไม่เกิดอะไรขึ้น
UploadManualView:145-177 ("ไฟล์ถูกเพิ่มเข้าคลังคู่มือแล้ว" + ปุ่มไปคลังที่ไม่มีไฟล์นั้น), SparePartsView:387-397 (ไม่ persist ไม่มีเลขที่คำขอ สต็อกไม่ลด), Sidebar:307-312 (ปุ่ม logout แค่ปิด dialog)
**ทำไมสำคัญ:** ในแอป operate ข้อความสำเร็จคือคำสัญญาเรื่องสถานะของโลกจริง ช่างที่เบิกลูกปืนแล้วไปที่คลังแต่ไม่มีคำขอ จะเลิกเชื่อ *ทุก* คำยืนยันในแอป รวมถึงอันที่จริง
**Fix:** ต่อสายให้ทำงานจริง หรือแปลงเป็น unavailable state ตาม pattern ที่ ScanMachineView:1092-1102 ทำไว้แล้ว — ห้ามขึ้นเครื่องหมายถูกสีเขียวให้ no-op

### [P0] อะไหล่และขั้นตอนปลอมถูกฉีดเข้าใบงานจริง
App.tsx:196-210 และ 239-259 แนบ `SP-BRG-6204`/`SP-OIL-SL2` (รหัสที่**ไม่มีใน mockData** ซึ่งใช้ `PART-NSK-7014`) + แผน LOTO 3 ขั้นที่ผู้ใช้ไม่ได้พิมพ์; WorkOrderDetailModal:36-42 render `FALLBACK_STEPS` 5 ขั้นที่ไม่มีใครเขียน เป็น *ตัว* checklist ให้ช่างติ๊ก
**ทำไมสำคัญ:** checklist คือเอกสาร safety/compliance ขั้นตอนที่ไม่มีใครเขียน + ช่างติ๊ก + วิศวกรอนุมัติ + ส่งออกรายงานรายเดือน = บันทึกซ่อมบำรุงที่ถูกปลอมแปลง และยังทำให้ dialog ยืนยันของ AI เป็นโมฆะ (ผู้ใช้ยืนยัน 3 field ระบบสร้าง 8)
**Fix:** ลบ fallback ทั้งสอง ส่งเฉพาะที่ฟอร์มเก็บมา; ใบงานที่ไม่มีแผนให้แสดง empty state ที่ให้ช่าง *เพิ่ม* ขั้นตอนเองพร้อมบันทึกว่าใครเพิ่ม

### [P1] สินค้าเดียวมี 3 threshold; action เดียวมี 2 ประสบการณ์
vibration 2.0 vs 2.5; temp >75 vs >80; CreateWorkOrderView:257-261 ตีป้ายเครื่อง `warning` ว่า "สถานะ: ปกติ" สีเขียว (CNC-04 ที่ 82.5°C + Err-E304 ก็ยังขึ้นเขียว); priority 3 ชุดสี; อนุมัติที่ PendingReview มี banner ที่ DetailModal เงียบ; H1 ขัดกับ TopBar 6 หน้า
**Fix:** `lib/thresholds.ts` export `SPINDLE_TEMP_MAX`/`VIBRATION_MAX` + `evaluateMachine()`; บังคับ status/priority ผ่าน pillStyles ทั้งหมด; หนึ่งหน้าหนึ่งชื่อ

### [P1] element ที่กดได้ไม่เป็น semantic — คีย์บอร์ด/screen reader ใช้ไม่ได้
`<div onClick>`/`<tr onClick>` ที่ Dashboard:367 (การ์ดเครื่อง), WorkOrderDetailModal:377 (checklist!), AllWorkOrders:164/247, CreateWorkOrderView:500, TopBar:226; `Modal.tsx` รับ `labelledBy` แต่**ไม่มี caller ไหนส่งเลย** → ทุก dialog เป็น `role="dialog"` ไร้ชื่อ; ไม่มี focus trap/restore; ไม่มี `aria-current`/`role="tab"`/`role="progressbar"` เลยทั้ง codebase
**Fix:** `<div onClick>` → `<button>` (checklist ใช้ `role="checkbox" aria-checked`); ส่ง `labelledBy` จากทุก ModalHeader; เพิ่ม focus trap ใน Modal; tab semantics ให้ทั้ง 4 กลุ่มแท็บ

### [P2] ไม่มีอะไรในสินค้ารู้ว่า "เลยกำหนด" แปลว่าอะไร
`dueDate` เป็นตัวเทาๆ text-xs ใน MyWorkOrders:168, AllWorkOrders:177, DetailModal:242 — ไม่มี overdue state, ไม่เรียงตามความเร่งด่วน, ไม่มีป้าย, badge ใน sidebar นับงานเปิด ไม่ใช่งานสาย
**ทำไมสำคัญ:** จุดประสงค์ทั้งหมดของศูนย์ซ่อมบำรุงคือไม่พลาดกำหนด ตอนนี้แอปเน้นขนาดไฟล์คู่มือมากกว่าใบงานที่เลยกำหนด 3 วัน
**Fix:** derive `isOverdue`/`dueSoon` ส่วนกลาง; เรียงตาม due date; การ์ดเลยกำหนดมีเส้นซ้าย + ป้าย "เลยกำหนด N วัน"; badge นับ overdue+review

## Questions to Consider

1. **ถ้าช่างไม่มีสัญญาณทั้งกะ แอปนี้คืออะไร?** ตอนนี้: หน้าตาปกติทุกอย่าง เสิร์ฟ mock หลัง toast 4 วินาที ปล่อยให้ติ๊ก checklist ความปลอดภัยแล้วกด "ส่งให้วิศวกรตรวจสอบ" ลงสุญญากาศ — ต้องเลือกว่าจะเป็น offline-first หรือ offline-honest ตอนนี้ยังไม่ใช่ทั้งคู่ มันคือ offline-deceptive
2. **ใครรับผิดชอบถ้อยคำใน `FALLBACK_STEPS`?** 5 ขั้นตอนที่ไม่มีใครเขียน ช่างติ๊ก วิศวกรอนุมัติ ส่งออกรายงาน ถ้า spindle พังหลังทำตามนั้น มันเป็นขั้นตอนของใคร — ตัดสินโดย const 6 บรรทัดบนหัวไฟล์
3. **ทำไมแอปรู้ว่าฉันยืนอยู่หน้าเครื่องไหน แล้วไม่เคยใช้ประโยชน์?** `activeMachine` ปักบน TopBar ทุกหน้า แต่อะไหล่ไม่กรอง คู่มือไม่กรอง ใบงานไม่กรอง แจ้งเตือนไม่พูดถึง — แอปมีข้อมูลที่มีค่าที่สุดในซอฟต์แวร์อุตสาหกรรม (ตำแหน่งกายภาพ) แล้วใช้มันเป็นชิปประดับ คำถาม generic-vs-authored ทั้งหมดยุบรวมลงที่ข้อนี้

# การวิเคราะห์ต้นทุน-ผลประโยชน์ (Cost-Benefit Analysis) โครงการ MT Center

**โครงการ:** MT Center — AI-CMMS (GS Battery Thailand)
**ขอบเขต:** วิเคราะห์การลงทุนขยายจาก POC สู่ Production ระยะ 5 ปี
**อัตราคิดลด (Discount Rate):** 12% ต่อปี
**สกุลเงิน:** บาท (THB)

---

**สรุป:** ทั้งสอง Scenario ให้ NPV เป็นบวกในกรอบ 5 ปี แต่ **Scenario A (Cloud) ให้ผลตอบแทนดีกว่าอย่างชัดเจน** — NPV สูงกว่ากว่า 200 เท่า, คืนทุนเร็วกว่าเกือบ 2 ปี, และ ROI/BCR สูงกว่ามาก เนื่องจากไม่ต้องลงทุน Hardware CapEx และค่าดำเนินการต่อปีต่ำกว่า ในขณะที่ Scenario B (On-Premise) มี NPV ที่บวกเพียงเล็กน้อย (ใกล้จุดคุ้มทุนพอดี) ทำให้มีความเสี่ยงสูงกว่ามากหากประมาณการคลาดเคลื่อน

## 5. Sensitivity Analysis

| กรณี | NPV Cloud | NPV On-Premise |
|---|---|---|
| **Base case** | 2,588,158 | 12,138 |
| **Tangible benefits ต่ำกว่าคาด 30%** | -771,823 | -3,347,843 |
| **Development cost บานปลาย 25%** | 1,688,158 | -1,137,862 |

**ข้อสังเกต:**
- หาก Tangible benefits ทำได้จริงต่ำกว่าคาด 30% ทั้งสอง Scenario จะพลิกเป็น NPV ติดลบ โดย On-Premise จะขาดทุนมากกว่า Cloud ถึงประมาณ 4.3 เท่า
- หาก Development cost บานปลาย 25% Cloud ยังคง NPV เป็นบวก (1,688,158) แต่ On-Premise จะพลิกเป็นลบทันที (-1,137,862) แสดงว่า Scenario B มีความอ่อนไหวต่อความคลาดเคลื่อนของต้นทุนสูงกว่ามาก
- Scenario A (Cloud) มี "buffer" ที่ทนทานต่อความคลาดเคลื่อนได้มากกว่า ในขณะที่ Scenario B อยู่ในจุดที่เปราะบาง (ใกล้จุดคุ้มทุน) แทบไม่มีช่องว่างรองรับความเสี่ยง

## 6. สรุปข้อเสนอแนะ

- แนะนำให้เลือก **Scenario A (Cloud)** เป็นแนวทางหลักในการนำ MT Center ขึ้น Production เนื่องจาก NPV, ROI, BCR และ Payback period ดีกว่า On-Premise อย่างมีนัยสำคัญ
- Scenario B (On-Premise) มี NPV ที่เป็นบวกเพียงเล็กน้อยและอ่อนไหวสูงต่อการเปลี่ยนแปลงสมมติฐาน จึงไม่ควรเลือกหากไม่มีเหตุผลเชิงนโยบาย (เช่น ข้อกำหนดด้าน Data Residency หรือความปลอดภัยข้อมูลที่บังคับให้ต้องเก็บ Data on-premise)
- ควรเร่งดำเนินการในช่วงปีที่ 1-2 เพื่อเข้าสู่จุดคุ้มทุนโดยเร็ว (Cloud คาดว่าคืนทุนในปีที่ 3) และควบคุมมิให้ Development cost บานปลายเกินแผน เนื่องจาก Sensitivity แสดงว่าเป็นปัจจัยกระทบสูง
- ควรทำ Pilot / Track KPI ของ Tangible benefits (Downtime, MTTR, ของสูญหาย, Productivity) อย่างใกล้ชิดในปีแรกของการใช้งานจริง เพื่อยืนยันว่าตัวเลขประมาณการใกล้เคียงความเป็นจริง ก่อนขยายผลเต็มรูปแบบ
- ควรพิจารณาแผนสำรอง (Hybrid หรือ phased rollout) หากพบว่า Tangible benefits ในปีแรกต่ำกว่าคาดเกิน 30% เพื่อปรับกลยุทธ์การลงทุนในปีถัดไป
